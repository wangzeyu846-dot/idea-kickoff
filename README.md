## 这是什么

这是一个供编码 AI 使用的开发工具包，包含规则卡、分阶段手册、流程管理和自检脚本。它帮助你把一句产品想法变成需求、代码和可以核对的结果，先做出本地可用的第一版，再按需要选择上线。

你不必先写完整 PRD，也不用先学技术栈、填配置表或决定开发阶段。AI 负责整理材料、创建目录、写代码、跑检查和记录进度；你负责说明真实问题、判断结果，以及确认费用和对外动作。

适合从一个具体问题开始，例如整理资料、生成初稿、分析内容或围绕业务资料问答。它提供的是工作流程和检查办法，产品效果仍要通过真实样例与试用反馈判断。

## 三步开工

**1. 下载工具包。** 在 GitHub 仓库文件列表上方点 **Code → Download ZIP**，下载并解压。整个文件夹就是你的工作空间，不必自己创建产品目录。

**2. 用编码 AI 打开文件夹。** 选择能读写本地文件、执行命令的工具，例如 [Claude Code](https://claude.com/claude-code)、[Codex](https://openai.com/codex/) 或 [Pi](https://pi.dev/)。完成所选工具的安装和账号配置后，在其中打开解压后的文件夹。仅能聊天的网页对话框无法执行这里的开发步骤。

**3. 说一句想法。** 例如：

```text
我想做一个把零散资料整理成报告的小工具，先在自己的电脑上试用，帮我开始。
```

AI 会先问当前最关键的 1—3 个业务问题，每轮最多 5 个，并给推荐理由。你可以回答“不确定”或“按推荐”；需求文档由 AI 整理。看不懂时，直接说“用产品语言再说一遍”。

有 PRD、评测、设计稿或参考截图，就发给 AI 或告诉它文件位置。已有材料和已定决策会复用，暂时没名字也能用工作名开工。需要明确指定规则时，可以说“请读取 AGENTS.md，按启动流程开始”。

下次继续，只要打开同一个文件夹，说“继续做 XX”。也可以双击 `开工.command` 启动；它会引导选择编码工具，并在工具退出后运行自检。详细步骤见[开始看这里](./开始看这里.md)。

## AI 做什么，你做什么

| 过程 | AI 负责 | 你负责 |
| --- | --- | --- |
| 明确需求 | 整理想法和已有材料，只补当前关键缺口 | 说清谁遇到什么问题、怎样才有用 |
| 确定第一版 | 给出实现建议、范围和分步计划 | 确认理解是否正确，费用和暂缓项是否可接受 |
| 验证核心功能 | 写代码、跑测试、准备真实模型样例 | 在需要时配置模型 Key，判断真实结果 |
| 做可用界面 | 实现页面、检查电脑和手机宽度 | 给视觉方向，实际点一遍并反馈 |
| 可选上线 | 核对平台条件、报价、部署和验证 | 完成本人账号授权，确认费用，核对线上结果 |
| 收尾与改进 | 整理使用方法、保存状态、复用样例验证改动 | 说出试用中最值得改的一件事 |

你可以选择本轮只做本地试用。中途停下来后，AI 会读取已有进度，不要求重新回答已确认的问题。开发分阶段进行，每次准备好实现与证据后，先通过当前版本自检，再由你明确说“验收通过”才能继续。

## 这版改进了什么

本衍生版在原工具包基础上，重点改善开工、恢复、验收和试用后的修改流程：

- **一句话开始。** AI 帮忙整理需求和工作名，不要求先填完模板或备齐后续素材。
- **少问当前无关的问题。** 默认只问 1—3 个关键业务问题；已有 PRD、评测、样例和决定直接复用。
- **卡住时仍知道下一步。** 说明已完成什么、哪些待验、同阶段还能做什么，以及确需你做的一件事。
- **接着做更清楚。** 保留进度和决策，恢复与双击入口用产品语言引导，不让你填写技术阶段编号。
- **改过之后重新验证。** 代码、提示词、需求和样例变动后，旧的成功不能直接当作本版通过；失败、中断或缺项也不能沿用旧结果。
- **试用后改一件最重要的事。** 反馈写回现有项目状态，关联原样例，明确最小改动和验收办法。

完整改动与兼容说明见[版本说明](./docs/手册/版本说明.md)。

## 怎么判断真的做完了

每个阶段都要交可核对的证据，放在对应产品的 `docs/evidence/`。按阶段适用性提供：

- 截图，以及你能打开的地址或“照着点”步骤。
- 是否表，说明测试、真实模型、数据恢复、密钥检查等是否完成。
- 自检原始输出，以及由实际模型调用生成的记录。

这些文件由 AI 和脚本维护，你无需编辑 JSON。是否表有“否”或“待验”，就不能宣布阶段完成；无代码阶段按适用项检查。缺模型 Key 时，AI 可以继续同阶段不依赖它的工作，真实效果仍保持待验。

自检会核对当前版本的证据，帮助减少遗漏；它不能代替业务判断，也不能证明结果对用户有用。你仍要看真实样例、实际操作。拿不准时，问 AI：“这项结论的证据在哪？”

规则同时要求：密钥不进仓库和前端，重要数据在重启后可恢复，上线时用户数据彼此隔离，涉及付费资源或对外动作先确认。规则和检查可以减少风险，实际产品仍须逐项验证。

## 使用范围与费用

- 当前面向 **Mac 上的网页 MVP**，支持先本地试用，再决定是否上线。Windows 尚未验证，不作为本版支持范围。
- 需要一个能操作本地项目的编码 AI 工具。Python、Node.js、Git 由 AI 开工前检查；缺少时给出安装步骤。
- 产品调用模型时需要相应 API Key，真实效果验收前要配置并运行。编码工具订阅、模型调用和云资源可能分别收费。
- 默认部署路径沿用腾讯云开发（CloudBase）。平台价格、免费额度、账号资格、界面及域名和运营要求可能变化，**实际开通前由 AI 核对并说明，涉及费用先由你确认**。
- 多个产品可以共用一个工具包，各自保存需求、代码和进度。已有云资源先核对能否复用，不默认再开付费资源。
- 高并发、大型系统、公开收费运营等需要单独评估容量、安全、成本和适用要求，本工具包不提供现成保证。

## 常见问题

**没有 PRD，可以开始吗？** 可以。先说谁遇到什么问题，AI 会整理；后续才需要的样例和账号不必提前备齐。

**试用后想继续改，是否要从头来？** 不需要。告诉 AI 哪里有用、哪里最费劲、下次先改哪一件，它会复用已有需求和评测。

**一个工具包能做多个产品吗？** 可以。说“我要做一个新产品，叫 XX”，AI 会创建独立目录。继续时说“继续做 XX”。

**AI 一次问太多怎么办？** 回“先问当前最关键的 1—3 个，给出推荐”。想自己复核自检时，让 AI 给出已填好产品名和阶段的完整命令即可。

## 文件与维护

普通使用者从[开始看这里](./开始看这里.md)进入；以下内容主要供 AI 和维护者使用。

```text
工具包/
├── AGENTS.md、CLAUDE.md       # AI 规则与工具入口
├── kit.sh、verify.sh         # 流程管理与自检
├── 开工.command              # Mac 双击入口
├── scripts/、tests/          # 检查辅助程序与工具包回归测试
├── docs/PRD模板.md           # AI 整理需求用
├── docs/手册/               # 开发、前端、部署手册与参考实现
└── projects/                # 一个产品一个文件夹，附空白模板
```

在工具包根目录运行维护检查：

```bash
python3 -B -m unittest discover -s tests -v
bash -n kit.sh verify.sh 开工.command
```

这些检查验证工具包自身，不能替代各产品的测试与真实模型验收。接入产品评测时，参考[最小评测与验收记录](./docs/手册/参考代码/最小评测/README.md)。

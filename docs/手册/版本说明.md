## 0.1.0 · 低门槛开发与阶段验收

日期：2026-11-18。

这个版本围绕非技术用户的产品实践，提供从想法整理、分阶段实现到结果验收的完整工作流程，重点覆盖开工、恢复、验证与试用反馈。

### 用户能感受到的变化

- 一句话即可开始，AI 帮忙整理需求和工作名；已有 PRD、评测、样例和决定直接复用。
- 通常只问当前关键的 1—3 个业务问题，每轮最多 5 个；后续才需要的材料注明准备时机。
- 在原需求字段中明确现有解决办法、本轮改善目标和可接受、不可接受的结果，不增加必填表单。
- 卡住时说明已完成什么、哪些尚未验证、同阶段还能做什么，以及用户下一步需要做什么。
- 旧项目恢复由 AI 读取已有记录，双击分岔使用中文业务选项，无需用户输入技术阶段编号。
- 试用反馈写入原有项目状态，关联样例，选一件最小改动继续验证。

### 工具包修复

- 自检必须指定有效阶段，缺少必要检查配置不会报告通过。
- 正式前端缺少工程或测试、静态检查、构建命令时，不会被当作不适用。
- 真实模型记录检查当前批次、实际状态、样例覆盖与对应输入；失败、中断、缺项或旧 Markdown 不能沿用旧成功。
- 代码、提示词、需求、样例等内容改变后，旧验证凭据失效；验证过程中改动也须重新检查。
- 自检一开始就记录本轮待验，强制中断也不会保留旧成功；旧批次不能覆盖新批次。
- 聊天和双击入口使用相同的验收检查，记录当前验收对应的验证编号。
- 首次双击会话中 AI 给产品目录改名后，窗口会接回同一产品；记录重复或缺失时停止核对，不猜测其他产品。

### 验证情况

本版本完成了 55 项离线回归测试，并通过 Shell 语法检查和独立代码评审。测试包含内容版本变化、失败与中断、聊天与双击推进、旧项目恢复、目录改名、前端检查缺项等路径。进程恢复测试实际执行启动、终止和随机标记落盘；产品测试与包管理命令使用隔离替身。

维护者可在工具包根目录执行：

```bash
python3 -B -m unittest discover -s tests -v
bash -n kit.sh verify.sh 开工.command
```

普通使用者无需运行工具包的回归测试，产品自检由 AI 按当前阶段执行。

这不代表真实模型效果、线上部署或非技术用户体验已经实测通过。模型效果需要真实样例，使用体验需要真实用户；部署平台的界面、价格、额度与适用规则应在实际操作前核对。

### 从旧工具包继续使用

保留原产品文件和已有决定，由 AI 读取当前项目状态后恢复。旧的可读冒烟记录可以保留，但不能直接转换成新格式的成功凭据；在已有授权和必要配置齐备后重新验证。新的机器记录由 AI 和脚本维护，不要求用户填写。

文件摘要不读取秘密配置或业务数据，也无法检测外部服务的变化；模型 Key、服务地址或运行时配置改变后，需要 AI 主动安排重验。记录用于减少误判，不提供请求防伪或身份认证。

### 交付范围

公开打包包含工具包及空白产品模板，不包含开发者个人产品、秘密配置和本机实施记录。
